# Zelda's Daughter — инструкции для агента

Мобильная изометрическая action-adventure с элементами survival и RPG (iOS/Android, вертикальный экран, один палец). Исекай: обычный человек без суперсил в равнодушном фэнтезийном мире. Автор — один человек + агенты. Проект начат в апреле 2026 и брошен; с 2026-09-30 — по процессам The Chest (`/var/www/html/thechest`), с 2026-10-07 **разработка заново** (ADR-0007): апрельский проект — справочник в `archive/2026-04/`.

## Читать первым
1. `project-design.md` — согласованный дизайн. Источник истины по продукту.
2. `plan/README.md` — как устроен план, формат задачи, ворота; такс-листы — `plan/stage-*.md`. **Галочки ставим только там.**
3. `NEXT.md` — что делать прямо сейчас (один экран).
4. `docs/agent-handbook.md` — хост, ПК автора, общие ресурсы с The Chest; темы — `docs/handbook/`. Новое общее знание — туда, а не в личную память инструмента.
5. `docs/april-review.md` — что из апреля стоит взять (правила, числа, тексты, конфиги, инструменты) и что нет; код не переносим, пишем заново.
6. `docs/decisions/` — ADR. Решение, принятое автором, записывается ADR и не переспрашивается.

## Зафиксированные решения (не переспрашивать)
- **Стиль:** 2D billboard-спрайты персонажей в 3D-мире (как Don't Starve), «книжная иллюстрация» — перо + акварель, палитра приглушённая тёплая. Персонажи, NPC, враги генерируются нейросетью на ПК автора (ADR-0001).
- **Движок:** Unity 6 LTS + URP (мобильный), та же версия редактора, что у The Chest (ADR-0002).
- **Где Unity:** только на ПК автора через мост MCP (TensorLay). На сервере — код, данные, тесты логики на `dotnet`, документы. Android-эмулятор на сервере не используем (ADR-0003).
- **Ассеты:** можно брать из купленной библиотеки автора (Asset Store) и докупать. Купленное лежит в `Assets/ThirdParty/` и **в git не попадает**; список пакетов — `docs/asset-licenses.md` (ADR-0004).
- **Разработка заново** (ADR-0007): чистый проект `ZeldaDaughter/`; апрель — только справочник.
- **Правила игры — в C#-ядре** `core/ZeldaDaughter.Core` без `UnityEngine`, тесты `dotnet test` на сервере; числа — в `data/*.json`; Unity — представление (ADR-0008).
- Без HUD (нет HP-баров и цифр), один палец (свайп / тап / лонг-пресс на персонаже), Kenshi-прогрессия, скрытый вес, автосейв, день/ночь 20–30 мин — подробности в `project-design.md`.

## Как работать с планом
- Начало сессии: `NEXT.md` → такс-лист текущего этапа → первая незанятая задача; в `NEXT.md` строка «В работе: <ID>, агент, дата».
- Перед видимой задачей — критерии в `docs/done-criteria/<ID>.md` **до** работы; не подгонять под результат.
- Во время: промежуточное — сразу в файлы; тесты до кода механики; коммит с ID задачи в сообщении.
- **Галочка — только с доказательством:** логика — зелёные тесты; видимое — кадр или запись экрана с телефона и строка `[ZD:*]` из `Player.log`/logcat; ощущение и вкус судит автор. Код Unity, написанный на сервере, не проверен, пока не собран на ПК, — так и писать.
- Конец: в `NEXT.md` заменить свой блок (в работе / дальше / ждёт автора), итог сессии — `docs/log/ГГГГ-ММ-ДД.md`.
- Вопрос автору — по одному, с 2–3 **действительно разными** вариантами и рекомендацией. Технические решения внутри задачи агент принимает сам и записывает.

## Как работать
- **Всё, что можно сделать кодом, делается кодом:** сцены из конфигов Editor-скриптами, префабы, материалы, компоненты — скриптами. Руками в Unity — только смотреть. Но **один** сборщик сцены из конфига, а не новый «фиксер» поверх старого: чинить причину, а не наслаивать.
- Мост Unity и видеокарта ПК **общие с The Chest**: занимать через busy-файлы (`docs/agent-handbook.md` §2), редактор не закрывать.
- Отладочный код (`RemoteInput`, диагностика, `ZD_DEBUG`) — только за `#if ZD_DEBUG`; в релизную сборку не попадает.
- Секреты (пароли, токены, ключи) — никогда в файлы репозитория, команды allowlist и коммиты. Репозиторий публичный (ADR-0006), пароль уже утекал (R0-01); сторож — `tools/hooks/guard.py`, `pre-commit`, защита пуша GitHub.
- Числа — с источником (замер, файл, ссылка); без замеров сроков и оценок не давать.
- Язык общения с автором — русский.

## Правила кода (C#)
- Namespaces: `ZeldaDaughter.{Input,Combat,Inventory,Progression,World,NPC,Save,UI,Rendering,Quest,Audio}`.
- Правила (жесты, бой, раны, прогрессия, вес, крафт, язык, время, сохранение) — в ядре `core/` без `UnityEngine`, тесты до кода (ADR-0008).
- Числа баланса — `data/*.json`; ScriptableObject — только для Unity-ассетов (спрайты, префабы, звуки); MonoBehaviour — показ и ввод.
- Системы общаются через C# events; без `FindObjectOfType`/`FindWithTag` в игровом цикле — ссылки через сборщик сцены.
- `[SerializeField] private` вместо `public`; composition over inheritance.

## Генерация 2D-арта
- ПК автора (RTX 4080) — SD WebUI Forge / ComfyUI, проброс на сервер через TensorLay; видеокарта общая с The Chest (busy-файл).
- Кадры концепта — внешние сервисы (автор, решение 2026-09-30); апрельский `character_pipeline` (Forge, без согласования ракурсов) — справочник, разбор в `docs/april-review.md`.
- Billboard-рендер героя пишется заново в R2-01 по идеям апреля (разбор там же).
