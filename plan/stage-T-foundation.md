### T-01 · Чистый проект скриптом
**Зачем.** Апрельский проект вырос из фиксов (ADR-0007); дизайн §11 — «всё, что можно, кодом».
**Что сделать.** 1) `Unity.exe -batchmode -createProject C:\dev\zelda\ZeldaDaughter` (не от администратора — задача планировщика `RunLevel Limited`, `docs/agent-handbook.md`). 2) `Packages/manifest.json` — только нужное: URP, Input System, Test Framework, Newtonsoft JSON, unity-mcp v10.2.0; без Cinemachine, Multiplayer Center, Visual Scripting, Timeline, Collab. 3) Editor-скрипт `ProjectSetup.Apply()` (идемпотентный, `-executeMethod`): URP-ассет для мобильных (без HDR, MSAA 2x, тени — одна каскадная, SRP Batcher вкл.), портрет, Android/iOS идентификатор `com.papergallery.zeldadaughter`, `activeInputHandler` = Input System, цветовое пространство Linear, сжатие ASTC. 4) `McpSharedServerGuard` (в своей сборке) — из `UnityProject` без изменений. 5) `.gitignore` проекта.
**Выход.** `ZeldaDaughter/` (Assets, Packages, ProjectSettings) в git.
**Готово, когда.** `-batchmode -executeMethod ProjectSetup.Report` печатает настройки, совпадающие с перечнем; 0 ошибок компиляции; повторный `Apply()` ничего не меняет (`git status` чистый). **Кто.** агент через мост. **Объём.** M.

### T-04 · Сцена из конфига
**Зачем.** Дизайн §1 «построение мира — конфиги с координатами»; в апреле было 17 сборщиков и «фиксеров» — теперь один.
**Что сделать.** `scenes/<имя>.json` — земля, свет, камера, точки (spawn, интересы), объекты по id префаба/примитива с координатами; `SceneBuilder.Build(configPath)` (Editor) пересобирает сцену целиком, идемпотентно; формат описан в `docs/scene-config.md`. Первая сцена — `scenes/g1-capsule.json`: плоскость 40×40, свет, камера, точка героя.
**Готово, когда.** два прогона сборщика дают один хеш содержимого `[ZD:Scene]` (имена, трансформы, компоненты; `.unity` побайтно не совпадает — новые fileID); в `Assets/Scenes/` только сцены из конфигов; конфиги проверяются тестами на сервере. **Кто.** агент. **Объём.** M. **Зависит от.** T-01.

### T-05 · Капсула идёт по свайпу
**Зачем.** G1: ощущение управления одним пальцем — до любой графики (§1: жесты, CharacterController).
**Что сделать.** `GestureInput` (Unity) — касания Input System → `GestureRecognizer` ядра (C-02) → `MoveIntent` → `CharacterController`; изометрическая камера (ортографическая или перспектива с узким углом — параметр конфига), следует за героем; строки `[ZD:Move]` (начало/конец свайпа, направление) и `[ZD:Gesture]` (тап/лонг-пресс).
**Готово, когда.** в редакторе с симуляцией касаний капсула идёт по направлению свайпа, лонг-пресс на капсуле не двигает её; на телефоне — в T-07. Видимое: критерии — `docs/done-criteria/T-05.md`. **Кто.** агент + мост. **Объём.** M. **Зависит от.** C-02, T-04.

### T-07 · Сборка на телефон
**Что сделать.** Навык `zd-build`: `BuildScript.Android(debug|release)` через `-executeMethod` (сборщик **не меняет** настройки проекта и материалы — урок апреля), `adb install -r`, запуск, `adb logcat -s Unity` → строки `[ZD:*]` на сервер; запись экрана `adb shell screenrecord` или `scrcpy --record`.
**Готово, когда.** G1: запись с телефона — капсула идёт по свайпу, в logcat `[ZD:Move]`; «годится» автора по ощущению. **Кто.** автор+агент. **Зависит от.** T-05; автор: модуль Android Build Support (Hub) и телефон с отладкой по USB. **Объём.** M.
