# Этап С — ядро правил на чистом C#

Цель: все правила игры из `project-design.md` §1, §3, §6, §7 — в библиотеке `core/ZeldaDaughter.Core` без `UnityEngine`, детерминированно (время и случайность приходят снаружи), с тестами `dotnet test` на сервере (ADR-0008). Unity в Т/Р2/В только показывает то, что решило ядро.

Почему этап целиком агентский: ни одна задача не требует Unity, ПК или вкуса автора. Числа баланса — в `data/*.json`, не в коде; читаются тестами и Unity одним загрузчиком.

Апрель — справочник (ADR-0007): правило или число из `archive/2026-04/UnityProject` берём, только если оно не противоречит дизайну, и с пометкой источника; код не переносим — пишем заново, сначала тест. Разбор апреля — `docs/april-review.md`.

### C-01 · Каркас ядра
**Что сделать.** `core/ZeldaDaughter.Core/` — `ZeldaDaughter.Core.csproj` (netstandard2.1, `LangVersion 9.0`, `Nullable enable`), `ZeldaDaughter.Core.asmdef` (`noEngineReferences: true`), `package.json` (`com.zeldadaughter.core`, `unity: 6000.3`); `core/ZeldaDaughter.Core.Tests/` (xUnit, net10.0 как у The Chest); `core/ZeldaDaughter.sln`; `global.json` при необходимости; `tools/check.sh` находит `core/*.sln`.
**Готово, когда.** `tools/check.sh` — `CHECK OK` с хотя бы одним тестом. **Кто.** агент. **Объём.** S.

### C-02 · Жесты
**Зачем.** §1 «Диспетчер жестов»: лонг-пресс — только если касание началось в зоне героя, удержание ≥ 0,5 с, смещение ≤ 20 px; сдвинул палец — свайп, даже если начал на герое; тап — < 0,5 с на объекте.
**Что сделать.** `GestureRecognizer`: вход — касания (время, экранная точка, «попал в героя / в объект id»), выход — события `SwipeStarted/SwipeUpdated(direction, strength)/SwipeEnded`, `Tap(target)`, `LongPressOnHero`. Пороги — `data/input.json` (в мм экрана и px — решить в задаче, DPI приходит снаружи). Тесты на границах порогов и на «начал на герое, сдвинул».
**Готово, когда.** тесты на все правила §1; нет зависимостей от Unity. **Кто.** агент. **Объём.** M.

### C-03 · Движение
**Что сделать.** `MoveIntent` из свайпа (направление в мировых осях с учётом угла камеры — параметр); `SpeedModel`: базовая скорость × поправки (перегруз — C-09, перелом — C-07, вода §1 — замедление, голод — C-08); всё в `data/movement.json`.
**Готово, когда.** тесты на каждую поправку и их сочетание. **Кто.** агент. **Объём.** S. **Зависит от.** C-02.

### C-04 · Время суток
**Что сделать.** `WorldClock`: игровое время из реального шага `dt`, длина цикла 20–30 мин (§2, `data/world.json`), фазы и плавные доли для света (Unity читает «насколько закат»); пропуск времени для сна (§6).
**Готово, когда.** тесты: полный цикл за заданное время, фазы в нужном порядке, промотка сна. **Кто.** агент. **Объём.** S.

### C-05 · Данные
**Что сделать.** `data/*.json` — предметы, рецепты, враги, раны, навыки, реплики; `DataSet.Load(dir)` (Newtonsoft — в Unity `com.unity.nuget.newtonsoft-json`); проверка ссылок (рецепт ссылается на существующие предметы, id единообразны — урок апреля `knife`/`item_knife`).
**Готово, когда.** тест загружает весь `data/` без ошибок; битая ссылка — понятная ошибка с файлом и id. **Кто.** агент. **Объём.** M. **Зависит от.** C-01.

### C-06 · Навыки по Kenshi
**Зачем.** §6: всё растёт через использование, в том числе неудачи; нет опыта.
**Что сделать.** `Skills`: набор навыков (сила, стойкость, точность, владение оружием по типам, грузоподъёмность, язык — C-11), события использования → прирост с убывающей отдачей; эффекты навыков — функции, которые читают другие системы.
**Готово, когда.** тесты: промах растит точность, урон растит стойкость, перегруз — грузоподъёмность; прирост убывает с уровнем. **Кто.** агент. **Объём.** M. **Зависит от.** C-05.

### C-07 · Раны и нокаут
**Зачем.** §6 «Раны и состояние», «Типы ран», «Лечение», «Нокаут».
**Что сделать.** `Condition`: раны (колотая/резаная → кровотечение, перелом → хромота/замедление, ожог → точность, отравление → тошнота), накопление, нокаут при критическом уровне, после нокаута раны остаются; лечение: само (медленно), отдых у костра/в таверне (быстрее, сон — до порога), лекарство (почти мгновенно). Визуальные признаки — набор флагов для Unity (хромает, держится за бок, кровь…).
**Готово, когда.** тесты на каждый тип, накопление → нокаут, три скорости лечения. **Кто.** агент. **Объём.** L. **Зависит от.** C-05.

### C-08 · Голод
**Что сделать.** Скрытый голод, порог → постепенная деградация всех характеристик; еда — слабое универсальное лечение + сытость; «есть нужно нечасто» — скорость из данных.
**Готово, когда.** тесты: порог, деградация, еда. **Кто.** агент. **Объём.** S. **Зависит от.** C-07.

### C-09 · Инвентарь и вес
**Что сделать.** Слоты (число из данных), скрытый вес предметов, порог грузоподъёмности → замедление движения и атак, реплика; рост грузоподъёмности от ходьбы с перегрузом (C-06).
**Готово, когда.** тесты: полный инвентарь, перегруз, рост. **Кто.** агент. **Объём.** M. **Зависит от.** C-06.

### C-10 · Крафт
**Что сделать.** Полевой крафт «предмет на предмет» (§7: палка + ткань = факел, нож + палка = заострённая палка, топор + дрова = доски); станки (плавильня, наковальня — оружие только там); логические цепочки (костёр: дрова в мире + кремень; факел зажигается у огня); подсказка-реплика, когда предмет рядом с подходящим объектом.
**Готово, когда.** тесты на все комбинации из §7, отказ без комбинации, «оружие только на наковальне». **Кто.** агент. **Объём.** M. **Зависит от.** C-09.

### C-11 · Язык
**Что сделать.** Понимание растёт от общения (§3, Kenshi-рост); этап 1 — только кракозябры + иконки, этап 2 (через 2–3 NPC) — проступают слова, этап 3 — нормальная речь с диалектом; `Scramble(text, understanding, seed)` — детерминированно: одно и то же слово у одного NPC одинаково.
**Готово, когда.** тесты: этапы по числу разговоров, детерминизм, доля понятных слов растёт. **Кто.** агент. **Объём.** M. **Зависит от.** C-06.

### C-12 · Реплики героя
**Что сделать.** `Remarks`: по состоянию (голод, раны, перегруз, ночь без огня, подсказки крафта) выбрать реплику из `data/remarks.json`; не чаще раза в N секунд на тему, без повторов подряд; тексты пишет content-writer.
**Готово, когда.** тесты на выбор и частоту. **Кто.** агент. **Объём.** M. **Зависит от.** C-07, C-08, C-09.

### C-13 · Сохранение
**Что сделать.** Снимок состояния ядра (герой, инвентарь, навыки, раны, время, язык, мир — по мере появления) в JSON с версией формата; один слот; восстановление даёт то же состояние (round-trip тест). Запись на диск и «при выходе/смене зоны/каждые N минут» — Unity-слой.
**Готово, когда.** round-trip тест на полный снимок. **Кто.** агент. **Объём.** M.

### C-14 · Онбординг
**Зачем.** §6 «Онбординг»: визуальные неблокирующие подсказки; каждая исчезает только после выполнения действия.
**Что сделать.** `Onboarding`: очередь подсказок из `data/onboarding.json` (свайп — сразу; тап — когда рядом есть объект; лонг-пресс — после первого предмета в инвентаре), «выполнено» — по событию жеста/игры; состояние в сохранении.
**Готово, когда.** тесты: подсказка видна до действия и пропадает после; следующая не раньше условия; после загрузки выполненные не возвращаются. **Кто.** агент. **Объём.** S.

### C-15 · Разговор этапа 1
**Зачем.** §2 «Пролог» (крестьянин общается жестами и иконками, показывает направление), §3 этап 1 и «провалы коммуникации».
**Что сделать.** `Conversation`: узлы из `data/dialogues.json` (реплика — текст для тарабарщины C-11 + иконки), ответы героя — иконками; «NPC не понял» по броску (C-11) → герой пробует другую иконку; итог узла — событие (жест «туда», ключ карты позже). Данные пролога: крестьянин (город на востоке — сверить с раскладкой), стражник.
**Готово, когда.** тесты: этап 1 — только иконки и тарабарщина; непонимание → вторая попытка; разговор засчитывается в понимание языка (C-11); данные проходят проверку ссылок. **Кто.** агент. **Объём.** M. **Зависит от.** C-11.
