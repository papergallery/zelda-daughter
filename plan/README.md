# Zelda's Daughter — план реанимации

Версия 0.1, 2026-09-30. Продукт — `../project-design.md`; этот план — как из апрельского сырья получить играбельные «первые 5 минут» на телефоне. Процессы взяты из The Chest (`/var/www/html/thechest/plan/README.md`) и упрощены под одного автора и мобильную игру.

> Сроков в днях нет — этапы, задачи с критериями «Готово, когда» и объём S/M/L/XL. Старый `roadmap.md` (226 галочек за 4 дня без проверки) — в `archive/2026-04/`, не источник статуса (ADR-0005).

## 1. Этапы и ворота

| Этап | Суть | Где | Ворота (судит автор) |
|---|---|---|---|
| **Р0** `stage-R0-revival.md` | Безопасность, гигиена репо, каркас процессов, реестр апрельского кода | сервер | — |
| **К** `stage-K-concept.md` | Концепт вида и первых 5 минут: кадры вертикального экрана в 2–3 разных направлениях, герой, сценарий страницей | ПК (генерация) + сервер | **GК** — выбран вид мира и героя |
| **Р1** `stage-R1-environment.md` | Unity 6 на ПК, мост, одна сцена из конфига, сборка на телефон, ядро логики на `dotnet` | ПК + сервер | **G1** — пустая сцена с героем-капсулой идёт по свайпу на телефоне |
| **Р2** `stage-R2-first-minutes.md` | Пролог: пробуждение у дороги → крестьянин в поле → путь к городу, в выбранном стиле | ПК + сервер | **G2** — автор проходит 5 минут на телефоне: «годится» |

К и Р1 идут параллельно: концепт не требует Unity, а окружение не требует решения о стиле. Р2 начинается после GК и G1. Этапы после G2 (город, инвентарь, бой…) заводятся по итогам G2 из апрельского реестра (`docs/inventory-2026-04.md`) — по одной системе за раз.

## 2. Формат задачи

```
### R1-04 · Название
**Зачем.** одна-две строки, ссылка на § дизайна.
**Что сделать.** нумерованные шаги.
**Выход.** артефакты с путями.
**Готово, когда.** проверяемые пункты; для видимого — какое доказательство (кадр/запись с телефона, строка лога).
**Кто.** автор / агент / автор+агент.
**Зависит от.** ID.
**Объём.** S / M / L / XL.
```

- ID: `R0-NN`, `K-NN`, `R1-NN`, `R2-NN`. Коммиты и ветки — с ID (`R1-04-logic-core`).
- Такс-лист в начале файла этапа — единственное место галочек. Строка такс-листа — название и одна короткая пометка.
- **Видимая задача** (всё, что игрок видит или слышит): критерии — в `docs/done-criteria/<ID>.md` до работы; порядок — концепт/референс → «годится» автора → реализация → кадр с телефона рядом с принятым концептом. Галочка — после «годится» автора.
- Роли: **автор** — ПК, телефон, вкус, покупки; **агент** — код, данные, тесты, документы на сервере; **автор+агент** — агент готовит, автор включает ПК/телефон и смотрит.

## 3. Как показываем автору

Вопросы автору — не очередью в чате, а **листом вкуса** к результату: страница с кадрами/видео и 3–7 вопросами «годится / переделать», по одному решению на вопрос, варианты действительно разные. Перед показом кадры смотрит критик кадров (`.claude/agents/frame-critic.md`, заводится в R0-07).

## 4. Риски

| Риск | Что делаем |
|---|---|
| 2D-герой и 3D-мир не сходятся по стилю | Решаем на концепте (этап К), до кода; несколько направлений мира, а не одно |
| Генерация не даёт стабильного персонажа в 4 направлениях и анимации | K-03 — проба пайплайна на одном герое до всего остального; запасной путь — cutout-анимация из частей |
| ПК, мост и видеокарта общие с The Chest | busy-файлы, работа окнами; тяжёлое The Chest не прерываем |
| Апрельский код не работает в Unity 6 | R1-01 фиксирует ошибки компиляции списком; чиним по системам, не всё разом |
| Лицензии купленных ассетов при публичном репо | `Assets/ThirdParty/` вне git (ADR-0004), репозиторий — приватный (R0-01) |
