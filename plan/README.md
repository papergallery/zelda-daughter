# Zelda's Daughter — план разработки

Версия 0.2, 2026-10-07. Продукт — `../project-design.md`; этот план — как из него получить играбельные «первые 5 минут», а затем стартовый регион на телефоне. Процессы — из The Chest (`/var/www/html/thechest/plan/README.md`), упрощены под одного автора и мобильную игру.

> **Пересмотр 2026-10-07 (ADR-0007).** Апрельский проект — не основа, а справочник в `archive/2026-04/`. Разработка идёт заново: чистый проект Unity, правила игры — в C#-ядре с тестами на сервере (ADR-0008). План 0.1 (реанимация: миграция, чистка «фиксеров», перенос апрельской логики) отменён; сделанное в нём, что остаётся в силе, — в такс-листах с пометкой.

> Сроков в днях нет — этапы, задачи с критериями «Готово, когда» и объём S/M/L/XL. Числа — только с источником.

## 1. Этапы и ворота

| Этап | Суть | Где | Ворота (судит автор) |
|---|---|---|---|
| **Р0** `stage-R0-revival.md` | Безопасность, гигиена, процессы, сторож правил, агенты | сервер | — |
| **К** `stage-K-concept.md` | Вид мира и героя: кадры вертикального экрана в 2–3 разных направлениях, герой, сценарий первых 5 минут | внешние сервисы (автор) + сервер | **GК** — выбраны вид мира и манера героя |
| **Т** `stage-T-foundation.md` | Чистый проект Unity, одна сцена из конфига, капсула-герой по свайпу, сборка на телефон | ПК + сервер | **G1** — капсула идёт по свайпу на телефоне, жесты — из ядра |
| **С** `stage-C-core.md` | Ядро правил на чистом C#: жесты, время суток, состояние героя, прогрессия, инвентарь и вес, крафт, язык, сохранение | сервер | — (зелёные тесты; читаются в Р2 и В) |
| **Р2** `stage-R2-first-minutes.md` | Пролог: пробуждение у дороги → крестьянин → край города, в выбранном стиле | ПК + сервер | **G2** — автор проходит 5 минут на телефоне: «годится» |
| **В** `stage-V-region.md` | Стартовый регион: лес/поляна + город, 7–8 NPC, бой, раны, крафт, торговля, карта, блокнот | ПК + сервер | **GВ** — регион на телефоне, все механики §1–9 на нём проверены |

```
Р0 ──► К (вид) ────────────────┐
   └─► Т (фундамент, G1) ──────┼──► Р2 (пролог, G2) ──► В (регион, GВ) ──► дальше: биомы, расы, монетизация
   └─► С (ядро, тесты) ────────┘
```

К, Т и С идут параллельно: концепт не требует Unity, фундамент не требует решения о стиле, ядро не требует ни того, ни другого. Р2 начинается после GК и G1 и берёт из С жесты, время суток и реплики. В — после G2; её задачи детализируются по итогам G2.

**Дорожки.** Автор: вкус (К, ворота), ПК и телефон (Т-сборка, G1, G2). Агент: ядро (С) — целиком на сервере; Unity-код — через мост на ПК (`docs/agent-handbook.md`).

## 2. Формат задачи

```
### T-04 · Название
**Зачем.** одна-две строки, ссылка на § дизайна.
**Что сделать.** нумерованные шаги.
**Выход.** артефакты с путями.
**Готово, когда.** проверяемые пункты; для видимого — какое доказательство (кадр/запись с телефона, строка лога).
**Кто.** автор / агент / автор+агент.
**Зависит от.** ID.
**Объём.** S / M / L / XL.
```

- ID: `R0-NN`, `K-NN`, `T-NN`, `C-NN`, `R2-NN`, `V-NN`. Коммиты — с ID.
- Такс-лист в начале файла этапа — единственное место галочек. Строка такс-листа — название и одна короткая пометка; у каждой строки есть раздел `### ID` (`tools/check-plan.py`).
- **Логика** (С) — «сделано» = зелёные тесты `tools/check.sh`; тесты пишутся до кода.
- **Видимая задача** (всё, что игрок видит или слышит): критерии — в `docs/done-criteria/<ID>.md` до работы; порядок — концепт/референс → «годится» автора → реализация → кадр/запись с телефона рядом с принятым концептом + строка `[ZD:*]` из `Player.log`/logcat. Галочка — после «годится» автора.
- **Код Unity, написанный на сервере**, не проверен, пока не скомпилирован на ПК (мост) — так и писать.
- Роли: **автор** — ПК, телефон, вкус, покупки; **агент** — код, данные, тесты, документы; **автор+агент** — агент готовит, автор включает ПК/телефон и смотрит.

### Правила видимых задач (ревью процесса 2026-10-08)
- Критерии видимой задачи: **п. 1 — склейка «кадр игры | концепт» узнаётся** (критик в режиме сравнения, ≥ 8/10, без нулей); остальное — средства.
- Изменение границ задачи — только новым ID; незавершённых задач с Unity — не больше двух.
- После каждой вехи вида — страница «до | после | концепт» автору без вопросов (ADR-0009), ссылка в `NEXT.md`.

## 3. Как показываем автору

Вопросы — не очередью в чате, а **листом вкуса** к результату: страница с кадрами/видео и 3–7 вопросами «годится / переделать», по одному решению на вопрос, варианты действительно разные. Перед показом кадры смотрит критик кадров (`.claude/agents/frame-critic.md`, R0-07). В автономной сессии вопросы копятся в `docs/for-author.md`, работа не встаёт.

## 4. Риски

| Риск | Что делаем |
|---|---|
| 2D-герой и 3D-мир не сходятся по стилю | Решаем на концепте (К), до кода вида; несколько направлений мира, а не одно |
| Генерация не даёт стабильного героя в 4 направлениях и анимации | K-03 — проба на одном герое до всего остального; запасной путь — cutout-анимация из частей |
| Управление одним пальцем «не ощущается» | G1 — капсула на телефоне до любой графики; пороги жестов — в данных, крутятся без пересборки ядра |
| ПК, мост и видеокарта общие с The Chest | Один сервер моста на два редактора (R1-02), busy-файлы, тяжёлое The Chest не прерываем |
| Апрельская структура протащится в новый проект | Апрель только читаем (ADR-0007); системы пишутся заново, сначала тесты |
| Лицензии купленных ассетов при публичном репо | `Assets/ThirdParty/` вне git (ADR-0004); репозиторий публичный по решению автора (ADR-0006) — в git только своё и CC0 |
