# ADR-0007 · Разработка заново: чистый проект Unity, апрель — только справочник

- **Статус:** принято
- **Дата:** 2026-10-07
- **Задача:** пересмотр плана (`plan/README.md` v0.2)
- **Кто решил:** автор («мы не берём старые задачи, а беремся за разработку проекта по новой… этот проект делался давно и неправильно»)

## Контекст
План 2026-09-30 строился как реанимация апрельского проекта: перевести `UnityProject` на Unity 6, вычистить 17 сборщиков-«фиксеров» и 52 сцены, вынести апрельскую логику в ядро, прогнать апрельские тесты (R1-04…R1-06, ADR-0005 «апрель — сырьё»). В апрельском проекте нет ни одной системы, проверенной на телефоне (`docs/inventory-2026-04.md`); структура выросла из фиксов (эмулятор, бисекция падений, перекраска материалов).

## Решение
1. Новый проект Unity — `ZeldaDaughter/` в корне репозитория (Unity 6000.3.24f1, URP для мобильных, портрет), создаётся скриптом. Имя папки — имя инстанса моста (`ZeldaDaughter@…`).
2. Апрельский `UnityProject/` переезжает в `archive/2026-04/UnityProject/` и не собирается. Из него можно читать идеи и формулы, но не переносить системы целиком: каждая система пишется заново по `project-design.md`, сначала тесты.
3. Задачи R1-04…R1-08 старого плана отменены; R1-01 (миграция апрельского проекта на Unity 6) остаётся в истории как сделанная, но её результат уходит в архив. R1-02 (общий мост) и R1-03 (история без секрета) остаются в силе.
4. ADR-0005 заменён этим решением.

## Альтернативы
- Чистить апрельский проект (старый R1-06) — дольше, чем написать заново, и тянет апрельскую структуру.
- Удалить апрельский код из репозитория — теряются формулы и идеи, которые полезно прочитать; в архиве они не мешают.

## Последствия
- `CLAUDE.md`: блок про апрельские `ZeldaDaughter.Rendering` и `character_pipeline` — справочный, не «написано».
- Мост: инстанс Zelda теперь `ZeldaDaughter@<hash>` (R1-02, `docs/agent-handbook.md`).
- `McpSharedServerGuard` переносится в новый проект — это не апрельский код.
