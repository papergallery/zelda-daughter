# ADR-0009 · Автономная демо-сборка: агент решает сам, ворота — после демо

- **Статус:** принято
- **Дата:** 2026-10-08
- **Задача:** этап Д (`plan/stage-D-demo.md`)
- **Кто решил:** автор (поручение), агент (всё, что внутри)

## Контекст
План 0.2 (`plan/README.md`) ведёт к игре через ворота автора: GК (вид мира и героя по концептам из внешних сервисов), G1 (капсула на телефоне), G2 (пролог на телефоне), и только потом регион (В). К утру 2026-10-08 ядро правил готово целиком (этап С, 141 тест), фундамент Unity есть (T-01…T-10), а этап К стоит: кадры концепта ждут автора.

Автор, 2026-10-08: «у тебя будет задача автономно предоставить мне демку, на которой я скорректирую дальнейший план развития. На вопросы отвечай сам (принимай решения сам). Мне нужен играбельный билд со всеми модельками (в проекте стиль выбран). Считай полноценная игра. Время не ограничено, токены тоже».

## Решение
1. Новый этап **Д — демо** (`plan/stage-D-demo.md`): играбельная сборка стартового региона (§2 «Прототип») со всеми механиками ядра в выбранном стиле — до ворот GК/G1/G2.
2. **Вопросы автору не задаются; решения принимает агент** и записывает каждое в `docs/demo/decisions.md` (что выбрал, почему, что было ещё). Открытые вопросы `docs/for-author.md` агент закрывает своими рекомендациями.
3. Ворота GК, G1, G2, GВ не отменены, а **сдвинуты на демо**: автор смотрит демо целиком и по нему корректирует план. Галочки этапов К/Р2/В не ставятся за демо — их задачи переоцениваются после показа.
4. Видимые задачи демо: критерии `docs/done-criteria/D-NN.md` до работы — как раньше. Доказательство — кадр из сборки/редактора и строка `[ZD:*]`. Вместо «годится» автора — критик кадров (`frame-critic`) и проход сборки агентом.
5. Остаются в силе: правила в ядре с тестами (ADR-0008), стиль billboard «перо + акварель» (ADR-0001), купленные ассеты не в git (ADR-0004), Unity только на ПК через мост (ADR-0003), секреты не в репозитории.

## Альтернативы
- Ждать ответов по К и идти по воротам — отвергнуто автором.
- Демо «на сером» (примитивы) — не то, что просил автор: «со всеми модельками».

## Последствия
- Направление мира и манеру героя выбирает агент (`docs/demo/decisions.md`); автор может отменить после показа — тогда меняются ассеты и шейдер, а не правила и сцены из конфигов.
- Демо-сборка: Windows (мышь = палец) и Android APK (если модуль поставлен; телефон автор подключит сам).
- Риск: много видимой работы без вкуса автора. Смягчение: стиль держится одного направления, всё собирается кодом из конфигов, поэтому перерисовка дешевле переделки.
