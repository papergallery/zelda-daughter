# Памятка агента: хост, ПК автора, общие ресурсы

Общее знание для любого агента (Claude Code, Codex). Перенесено из личной памяти Claude Code 2026-09-30. **Новое общее знание — сюда или в `handbook/`**, личная память — только для настроек инструмента. Порядок чтения: `CLAUDE.md` → `NEXT.md` → `plan/`.

## 1. Хост (сервер)
- 4 ядра, 7,7 ГБ ОЗУ (свободно ≈ 3 ГБ, своп в ходу), GPU нет, диск 118 ГБ — **свободно ≈ 13 ГБ** (2026-09-30). Здесь же The Chest (сайт, cron, агенты) и чужие сервисы.
- Unity, Android SDK, JDK, Xvfb на сервере **нет** и не ставим (ADR-0003). Лицензия Unity осталась в `~/.config/unity3d/`, не нужна.
- Тяжёлое (`dotnet build|test`) — только под общей с The Chest блокировкой: `flock -o /tmp/thechest-heavy.lock …` (`-o` обязательно, см. `thechest/docs/agent-handbook.md` §2 п. 3).
- `git-lfs` — `~/bin/git-lfs`, не в PATH; `git lfs install` на сервере не делать (ставит хуки, ломающие push).
- `gh` нет; GitHub API — `curl` с токеном из `~/.config/gh/hosts.yml` (токен в вывод не печатать).

## 2. ПК автора и общие с The Chest ресурсы
- **Ресурсы — `tools/resources.sh`** (автор 2026-10-07: «следи за памятью и хранилкой»): диск и память сервера и ПК. Пороги: сервер — диск < 3 ГБ или память < 1 ГБ → не собирать, чистить scratchpad; ПК — C: < 20 ГБ или память < 4 ГБ → не запускать Unity. В автономной сессии — на каждом будильнике.
- ПК: RTX 4080 16 ГБ. Туннель TensorLay пробрасывает порты ПК на `127.0.0.1` сервера (подробно — `thechest/docs/handbook/access.md`). Жив ли — `curl -s -o /dev/null -w '%{http_code}' 127.0.0.1:6510/` (`000` — ПК выключен или туннель лежит).
- **Мост Unity MCP The Chest — порт 6510.** Для Zelda — отдельный порт (R1-02, ещё не настроен). Не трогать мост The Chest из этого проекта.
- **Busy-файлы общие:** видеокарта — `/tmp/thechest-gpu.busy` (генерация арта Zelda тоже её занимает), редактор Zelda — `/tmp/zelda-unity.busy`. Занять: `echo "<агент> <ID> $(date -Is)" > файл`; освободить: `: > файл`. Чужой busy — ждать.
- **Очередь на редактор внутри сессии Zelda (с 2026-10-08):** когда несколько субагентов одной сессии работают с Unity, редактор занимают по очереди через `/tmp/zelda-editor-turn` (запись `<агент> <ID> <время>`; пусто — свободно). Чужая запись — писать код на сервере и ждать; после сборки/тестов/кадров — освободить `: > /tmp/zelda-editor-turn`. `/tmp/zelda-unity.busy` при этом держит сессия целиком.
- Генерация картинок — ComfyUI `8188` / SD Forge `7860` на ПК (поднимает автор). Пайплайн — `/var/www/html/Other/gpu-tunnel/character_pipeline/`.
- Редактор не закрывать и не убивать — с ним умирает мост. Мост молчит после сборки — почти всегда модальное окно.
- Клон на ПК — `C:\dev\zelda` (план, R1-01). Репозиторий — `github.com/papergallery/zelda-daughter`, **публичный** (ADR-0006): всё, что в git, видно всем. Push с сервера — deploy key `~/.ssh/zelda_deploy`, хост `github.com-zelda` в `~/.ssh/config` (remote `git@github.com-zelda:papergallery/zelda-daughter.git`), с 2026-10-07.
- **Скрипты для ПК — `tools/pc/`** (README там): синхронизация клона, перекомпиляция, состояние компиляции, консоль, сборка сцен, настройки проекта.
- **Командный мост TensorLay — `127.0.0.1:6520` (с 2026-10-07):** команды на ПК без Unity — PowerShell, файлы, процессы. Включает автор в TensorLay (Settings → Command bridge; красный баннер в заголовке — мост жив). Клиент — `python3 /var/www/html/Other/tensorlay/tools/bridge/tlbridge.py ping|health|exec|put|get|gpu`, токен — `~/.tensorlay_bridge_token` (600, вне репо; не печатать). `ping` без токена: `ok` — мост жив. **`spawn` в TensorLay 0.9.28 падает** (исправлено в 0.9.29) («StandardOutputEncoding is only supported when standard output is redirected») — долгий процесс запускать через `exec 'Start-Process … -PassThru'`. Вывод PowerShell начинается с мусора `#< CLIXML` — отфильтровать или `$ProgressPreference="SilentlyContinue"`.
- **Туннель TensorLay рвался каждые 14–24 мин (найдено 2026-10-07):** SSH.NET не отвечает на keepalive sshd (`/etc/ssh/sshd_config.d/60-keepalive.conf`: 30 с × 3), сессия `tensorlay` кончалась `Timeout, client not responding` (`sudo journalctl _COMM=sshd | grep tensorlay`), переподключение — ≈ 3 мин. Исправлено в TensorLay 0.9.29 (`KeepAliveInterval` 15 с): у автора стоит с 2026-10-07, туннель живёт > 30 мин без обхода (проверено 23:08). Обход `~/bin/tensorlay-keepalive.sh` (стук каждые 20 с) снят из cron, скрипт оставлен на случай отката.
- **Туннель TensorLay после обрыва сети сам не поднимался — до 0.9.30 (найдено 2026-10-08):** `AutoReconnectLoop` с v0.7.8 нигде не вызывался, а окно продолжало показывать «Connected». Сеть ПК пропала в 00:11 и к 05:04 вернулась, но за всё это время туннель ни разу не пытался подключиться. Исправлено в 0.9.30 (TensorLay `2309b9f`): цикл стартует после Connect и живёт до Disconnect. Проверено на сервере стендом (отдельный sshd + прокси-«чёрная дыра» на 40 с): туннель поднялся через 26 с после возврата сети. Признак у агента: `ss -tln` без 6520/7860 и в `journalctl _COMM=sshd` нет `Accepted … tensorlay` с адреса автора.
- **Туннель «жив, но молчит» (2026-10-08, 10:05–10:52):** порты 6520/8188 слушают, сессия `sshd: tensorlay` жива и ест CPU, а запросы висят (Recv-Q растёт, `curl` таймаут). Вероятно, зависшие каналы проброса в SSH.NET на ПК. Лечение с сервера: `sudo kill <pid сессии sshd: tensorlay>` (`ps aux | grep "sshd: tensorlay"`) — TensorLay 0.9.30 переподключается за 2 с. Висящие у себя `tlbridge`/`curl` — убить. В TensorLay стоит добавить проверку живости каналов (не только `IsConnected`).
- **Мост Zelda (R1-02, схема Б автора, 2026-10-07) — общий сервер 6510 с The Chest.** Пакет `com.coplaydev.unity-mcp` v10.2.0 (как у The Chest) хранит настройки в EditorPrefs, общих для всех проектов ПК; сервер на 6510 запускает редактор The Chest. Редактор Zelda только подключается к нему (`ZeldaDaughter/Assets/Scripts/Editor/Mcp/McpSharedServerGuard.cs`: подключение без запуска сервера; перед выходом стирает «рукопожатие» сервера, иначе пакет погасил бы сервер The Chest — проверено 3 закрытиями 2026-10-07, pid сервера тот же). Инстанс Zelda называется по папке — **`ZeldaDaughter@24ee0fcd79850490`** (с T-02, 2026-10-07; апрельский был `UnityProject@b19b854388a14b5b`) (The Chest — `TheChest@fa4255dcb19e821f`). **Первый вызов любой сессии — `set_active_instance` с `ZeldaDaughter@…`**: при двух редакторах сервер без выбора отказывает всем. **Путь с сервера — через мост TensorLay, без туннеля 6510** (TensorLay 6510 не пробрасывает, relay его не разрешает): клиент лежит на ПК — `C:\dev\zelda-tools\umcp.py` (копия `/var/www/html/thechest/tools/umcp.py`, обновлять `tlbridge.py put`), запуск — `& C:\Users\paper\.local\bin\uv.exe run --no-project python C:\dev\zelda-tools\umcp.py …` с `$env:UMCP_PROJECT="UnityProject"`. JSON-аргументы PowerShell 5.1 портит в строке `exec` — команду класть `.ps1`-файлом (`put`), JSON в нём — `'{\"k\":\"v\"}'`; образец — `C:\dev\zelda-tools\zd-console.ps1`. Встроенные инструменты `mcp__unity-mcp__*` в сессии Zelda не используются (`.mcp.json` пуст). Сервер не останавливать и не перезапускать — он The Chest. Пока проект открыт в редакторе, `-batchmode` по нему не запускать. Редактор Zelda запускать **не от администратора**: мост TensorLay работает с правами администратора, и `Start-Process` из него даёт окно «Administrator:» и файлы с владельцем «Администраторы» — запуск через задачу планировщика с `-RunLevel Limited` (`New-ScheduledTaskPrincipal -UserId PAPER\paper`), владельца — `icacls … /setowner "*<SID пользователя>"` (имя `paper` icacls путает с компьютером PAPER).

## 3. Грабли апреля, которые ещё актуальны
- **Library/Temp.** Не удалять `Library/` и `Temp/` целиком — полный переимпорт (в апреле 60+ мин на сервере). Застрявший лок — удалить только `Temp/UnityLockfile`, предварительно убедившись, что редактор не запущен.
- **Unity не видит `adb shell input tap/swipe`** (проверено на эмуляторе 2026-04): события не доходят. Для автоматического ввода — отладочный приёмник команд (`RemoteInputReceiver`, только за `#if ZD_DEBUG`) или `adb shell monkey`; на реальном телефоне ощущение управления проверяет автор.
- **Конвертация моделей через Blender** — долго и ненадёжно; сначала искать готовый формат (пожелание автора).
- **Материалы.** Апрельский `AndroidBuilder` выключал URP и перекрашивал материалы при каждой сборке — сборщик не должен менять настройки проекта (R1-06).
- Грабли Unity 6 / Asset Store / мост — общие с The Chest: `thechest/docs/handbook/unity.md`.

## 4. Как работать
- Вопросы автору — по одному, варианты принципиально разные, с рекомендацией (пожелание автора).
- Коммит после каждого законченного шага с ID задачи; после успешной сборки — обязательно.
- Секреты — никогда в репозиторий, allowlist, логи, коммиты.
