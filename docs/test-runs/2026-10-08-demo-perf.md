# 2026-10-08 · D-19 — производительность демо (Windows-плеер, ПК автора)

**Предварительный замер (до D-22b).** После коммита D-22b (земля шейдером, акварельные спрайты травы) замер повторить — цифры могут уйти вверх (`tools/pc/zd-perf.ps1`). Здесь записано, как мерили и что вышло сейчас.

## Как мерили
- Сборка `BuildScript.WindowsPerf` (`C:\dev\zelda-builds\perf\`): релиз (без Development, без сокета профайлера и окна брандмауэра) + `ZD_DEBUG`, нужен только `PerfProbe`. Размер 380,8 МБ (с `Assets/ThirdParty`).
- Запуск `tools/pc/zd-perf.ps1`: окно 1080×2340 (`-screen-width 1080 -screen-height 2340 -screen-fullscreen 0`), `-zd-perf-seconds 60`: героиня идёт на восток по региону по `CharacterController` (2,5 м/с), `vSyncCount = 0`, `targetFrameRate = -1` (мерим цену кадра, а не частоту монитора), `runInBackground`.
- Железо: RTX 4080, ПК автора, редактор Unity открыт, но простаивает; видеокарту делит с The Chest (на момент замера генерации не было — не проверялось).
- Метрики — `[ZD:Perf]` в журнале плеера (`PerfProbe`): 1 % худших = среднее по самой медленной сотой доле кадров.

## Оговорки
- **Телефона нет — на телефоне «не мерили».** Цифры RTX 4080 для мобильного GPU ничего не говорят; прикидка по цене кадра: пост-эффект акварели (полноэкранный проход), мягкие тени, 6462 объекта региона — на телефоне нужен замер (G1).
- Окно «1080×2340» на мониторе ниже 2340 px Unity может ужать до размера экрана; фактическое разрешение рендера в журнале не печатается — заметить в следующем замере (`Screen.width/height` в `PerfProbe`).
- Выборка ограничена 120 000 кадрами (≈ 46 с при 2600 fps); для 60 FPS-ограничения хватало бы с запасом.
- Время «до управления» отдельно не измерено: `first_frame` — первый кадр после загрузки сцены, `GameSession` в этот момент уже готова (`[ZD:Session] ready` раньше `first_frame` в журнале). Запуск до окна (инициализация движка, заставка) в 2,89 с входит.
