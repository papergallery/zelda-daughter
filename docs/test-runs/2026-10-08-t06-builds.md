# 2026-10-08 · T-06 отладка за ZD_DEBUG — проверка на Windows-сборках

Android-модуля на ПК нет (T-07 ждёт автора), поэтому правило «в релизе нет отладочных типов» проверено на Windows (Mono) — та же сборка `ZeldaDaughter.dll`.

- Сборки: `BuildScript.WindowsRelease()` / `WindowsDebug()` через мост; `[ZD:Build] StandaloneWindows64 debug result=Succeeded size=155,1MB time=23s`; релиз — 93,0 МБ (папка), отладка — 155,3 МБ. Сборщик сам настроек не меняет, но **первая сборка** проекта дописала данные Unity/URP: в `URP_Mobile.asset` — фильтрацию шейдерных ключей (`m_Prefilter*`), в `DefaultVolumeProfile.asset` — все компоненты Volume, в глобальные настройки URP — список, в `ProjectSettings` — пакетную отрисовку для Standalone; плюс сцена — `BuildScript` пересобирал её из конфига (новые fileID). Исправлено: сборка больше не пересобирает сцены; изменения Unity — в git; повторная сборка проверена ниже.
- Имена типов в метаданных `ZeldaDaughter_Data/Managed/ZeldaDaughter.dll`:
  - release: `PerfProbe=False DebugTools=False HeroController=True IsoCamera=True ZdLog=True`
  - debug: `PerfProbe=True DebugTools=True HeroController=True IsoCamera=True ZdLog=True`
- Отладочный плеер, 15 с без окна (`-batchmode -nographics`): `[ZD:Data] loaded items=31 recipes=7`, `[ZD:Perf] first_frame=0,72s`, `[ZD:Perf] … mem=42MB`; исключений и ошибок в журнале нет. fps в batchmode без отрисовки не показателен — замер на телефоне в T-08.
- Повторная релизная сборка после коммита изменений Unity: `[ZD:Build] StandaloneWindows64 release result=Succeeded size=92,9MB time=20s`, `git status` на ПК — **чистый**.
- Попутно: `zd-sync` переписал открытую сцену → модальное окно Unity «modified externally» заглушило мост на ~20 мин; теперь `zd-sync` нажимает Reload (`tools/pc/zd-reload.ps1`). Отладочный плеер вызвал окно брандмауэра Windows (порт профайлера) — системное, мостом не закрывается, ждёт автора.
